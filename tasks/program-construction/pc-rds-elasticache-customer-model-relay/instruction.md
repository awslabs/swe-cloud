Build `/app/program`, a multi-tenant HTTP server that sells customers access to AI models through upstream channels, reproducing the observable behaviour of the reference executable `/reference/program`.

Several customers share one server. Each owns API tokens with their own quota, expiry, model allowlist and subnet restriction, manages them and their account through a JSON management API (access token or login session), and spends them on the OpenAI-style relay: chat (plain and streamed), completions, embeddings, moderations, images, speech and model listing. The server forwards each request to an OpenAI-compatible upstream channel of the customer's group, returns the upstream's reply, and charges the price to the calling customer and token only. Administrators manage users, channels (including channel tests), redemption codes, top-ups, logs and, as root, server options. Records live in PostgreSQL (AWS RDS in the local Floci emulator); per-user, per-key and per-group cache entries and request rate limits live in Valkey (ElastiCache).

Start with `/docs/interface.md`: invocation, environment, AWS setup, the tables tests provision, the endpoints in scope, the graded configuration, exclusions and how results are compared. Then run the reference yourself against your own Floci resources and small stub upstreams to discover what the guide leaves open: validation and update rules, role checks, list ordering and filters, pricing and rounding per endpoint, refusal statuses, channel selection, low-balance handling, rate limits, and when cache entries are written, updated and expire.

Grading starts your program against fresh resources (and a second, rate-limited instance), provisions customers, administrators, groups and stub channels, and checks HTTP responses together with Postgres rows and Valkey entries, including that customers never see, modify or pay for each other's tokens and usage.

Write your source and `/app/build.sh`, which must produce `/app/program`; only `/app` is kept for grading. Use any installed language. Use the reference only by running it; do not copy or decompile it.

Only /app transfers; build.sh and program run offline as candidate with PATH=/usr/local/bin:/usr/bin:/bin and the AWS endpoint settings of this environment.
