# Executor integration

The executor is a separate service. A Running workflow with sync_holding and a matching SQL reservation produces a root launch request containing the workflow snapshot and uid. A root may run a single payload or expand a workflow DAG into a finite tree of node payloads. The workflow's one SQL reservation covers the entire tree, including queued descendants. Node IDs are globally unique strings, never reused. The root node ID is the workflow uid; other node IDs do not equal workflow uids. Each nonroot node has exactly one parent.

Receipts share the cluster workflow table under `wf_key="@run/" + node_id`. They are not workflows. Each receipt has monotone boolean fields `closed`, `started`, and `done` (missing means false), and may have an append-only DynamoDB string set `children` of direct child IDs (missing means empty). Nodes and edges remain for the deployment's lifetime. Consistent reads and ordinary conditional UpdateItem semantics apply. `executor_api.py` is the integration client's implementation of publication, delivery and payload completion.

Before issuing a child launch request, a worker atomically adds its child ID to the parent's children set with condition `(attribute_not_exists(closed) OR closed=false) AND started=true`. Successful registration is durable before delivery is queued. A rejected registration issues no request. Publication retries may arrive after the parent payload reports done. Expansion has no documented maximum depth. Node IDs and parentage are immutable; no unregistered node can launch.

On delivery the executor atomically sets the target node's started=true with condition `(attribute_not_exists(closed) OR closed=false) AND attribute_not_exists(started)`. Delivery reads neither SQL, workflow API objects, nor ancestor receipts. Requests can be delayed or duplicated without a maximum age, including after cancellation or name reuse. The executor runs each successfully started payload independently, then sets that node's done=true. Parent done certifies only that parent's payload; it says nothing about descendants or publication retries. Retries never start a second payload for one node ID.

The controller may set closed=true on any node receipt, including an absent receipt. Closed prevents that node's future start and further direct-child registration. It neither stops already-started payloads nor changes descendants' receipts. Controllers must preserve executor fields, membership and receipts; replacing an item can lose concurrent evidence. A failed API operation provides no evidence. Reads and writes across receipts or SQL are not atomic.

For normal work the executor writes exec_done to the matching workflow incarnation once all payloads and publications have finished; root done alone does not cause this notification. Live Pending and Running workflows must remain launchable, including their descendants. Cancellation does not terminate payloads. The executor neither closes receipts nor cleans synchronization rows. Only the owning deployment can finalize a cancelled tree. A new workflow uid has an independent tree and must not inherit the old tree's completion or SQL grant.
